# Musubi 영화 추천 정책

## 현재 적용한 추천 구조

추천은 사용자가 직접 선택한 취향과 영화 행동을 함께 사용하되 두 데이터를
분리해서 보관한다. 좋아요는 명시적 장르·배우·키워드 배열을 변경하지 않는다.
핵심 취향으로 수집하는 항목은 장르, 배우, 키워드이며 감독과 언어를 핵심
취향 점수로 무제한 누적하지 않는다.

행동별 학습 강도는 다음과 같다.

| 행동 | 기본 강도 | 처리 방식 |
| --- | ---: | --- |
| 상세 조회 | 0.1 | 같은 영화의 같은 날 반복 조회는 한 번만 반영 |
| 검색 후 클릭 | 1.5 | 명확한 관심 행동으로 처리하고 제한적으로 재노출 |
| 좋아요 | 3.0 | 가장 강한 관심 행동으로 처리하고 개인화 추천에 유지 |

한 영화가 가진 모든 메타데이터에 행동 점수를 그대로 복제하지 않는다. 영화당
학습량을 장르 57%, 키워드 35%, 배우 8%로 나누고, 배우는 상위 3명,
키워드는 상위 8개까지만 사용한다. 장르는 영화별 가중치 0.6 이상만 학습하고
강한 장르에 더 많은 점수를 배분한다. 행동 점수에는 30일 반감기를 적용한다.

## 추천 점수

개인화 유사도는 다음 요소를 사용한다.

| 요소 | 최대 가중치 |
| --- | ---: |
| 장르 | 3.5 |
| 키워드 | 2.5 |
| 배우 | 0.5 |
| 제작 국가·언어 | 1.0 |
| 관심 영화와 개봉 시기 유사성 | 0.5 |
| TMDB 보정 평점 | 1.0 |
| 기존 행동 영화 | 좋아요 최대 1.2, 검색 클릭 최대 0.6, 조회 최대 0.15 추가 |

제작 국가, 언어, 개봉 시기는 최근 1년 동안 관심을 보인 영화에서 계산하는 보조
신호다. 값이 없는 영화에는 임의 값을 넣지 않는다.

TMDB 평점은 원점수를 그대로 사용하지 않고 투표 수 100개를 기준으로 전체
평균에 수렴시키는 베이지안 보정을 적용한다. 따라서 투표 1~2개의 10점 영화가
투표가 충분한 영화보다 자동으로 앞서지 않는다. 단, 사용자가 직접 검색하거나
좋아요한 영화는 투표 수와 무관하게 최근 관심 영화로 노출할 수 있다.

최종 목록은 영화별 장르 가중치로 동일 장르 조합의 연속 독점을 줄이는 다양성
재정렬을 거친다. 좋아요 영화는 가장 강한 취향 학습 근거로 사용하지만 추천
카드에는 다시 노출하지 않는다. 검색 클릭·단순 조회 이력이 있는 영화는 전체
결과의 33%까지만 허용하고, 나머지는 아직 행동하지 않은 취향 유사 영화로
구성한다. 최근 본 영화와 마이페이지 좋아요 목록처럼 기록 확인이 목적인 영역은
이 제외 정책의 대상이 아니다.

`/recommendation`에는 장르·배우·키워드·국가·언어·개봉 시기와 보정 평점을 함께
계산한 종합 개인화 섹션을 제공한다. 개별 상위 취향 섹션은 취향의 근거를
설명하고 탐색 선택지를 넓히는 보조 섹션으로 유지한다.

## 취향 수정과 재계산

회원이 마이페이지에서 취향을 수정하면 브라우저뿐 아니라 서버에도 저장한다.
변경 시 기존 행동 기록을 한국 날짜 기준으로 일별 중복 제거한 뒤 행동 취향
점수만 다시 계산한다. 직접 선택한 취향은 추천 요청 시 행동 취향과 결합하므로
좋아요 추가·취소가 직접 선택값을 수정하지 않는다. 로컬 개발 DB의 기존 사용자
점수도 2026-08-06에 새 기준으로 재계산했다.

재계산 명령은 다음과 같다. 기본적으로 로컬 DB에서만 실행된다.

```bash
docker compose run --rm backend python scripts/rebuild_preference_scores.py
```

## 운영 이후 모니터링 계획

현재는 운영 인프라와 실제 사용자 트래픽이 없어 추천 품질 모니터링을 적용하지
않는다. 서비스 배포와 안정화 이후 다음 지표를 수집해 가중치를 조정한다.

- 추천 노출 대비 상세 클릭률
- 추천 영화 좋아요·찜 전환율
- 추천 순위별 클릭률
- 최근 관심 영화 재클릭률
- 추천 결과의 장르·제작 국가 다양성
- 추천 결과에서 낮은 투표 수 영화가 차지하는 비율
- 추천 요청 응답 시간과 오류율

초기 가중치는 임시 운영 기준이며 실제 지표 없이 임의로 최적값이라고 간주하지
않는다. 충분한 트래픽이 쌓인 뒤 기간별 비교 또는 A/B 테스트로 조정한다.
