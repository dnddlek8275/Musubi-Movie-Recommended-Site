# AI 주제 추천 근거 검증과 개선 절차

작성일: 2026-08-12

## 목적

사용자가 `코딩 관련 영화`, `양자 컴퓨팅을 다룬 영화`처럼 장르가 아닌
소재를 요청했을 때, 제목의 우연한 문자열 일치나 LLM의 추측으로 무관한 영화를
추천하지 않도록 한다. 모르는 표현을 무조건 아는 척하는 대신 확인 가능한 영화
메타데이터만 근거로 사용한다.

## 현재 처리 순서

1. `AI/data/topic_profiles.json`의 검토된 별칭과 검색어를 먼저 확인한다.
2. 등록되지 않은 명시적 주제는 사용자 원문에 있는 단어만 추출한다.
3. Milvus가 찾은 후보의 줄거리·키워드·벡터 원문·장르·배우·감독에서 원문 또는
   검토된 근거 단어가 실제로 존재하는지 검사한다.
4. 근거가 있는 후보만 GPU CrossEncoder 재정렬에 보낸다.
5. 근거가 없으면 결과 수를 맞추기 위해 다른 영화를 채우지 않고, 사용자에게
   비슷한 표현이나 더 넓은 주제를 묻는다.
6. 추천 이유도 후보에서 실제로 확인된 단어로만 만든다.

LLM이 생성한 해석은 검색 보조가 될 수 있지만 영화가 해당 소재라는 증거로
사용하지 않는다. 특히 미등록 주제에는 임의 동의어를 추가하지 않는다.

## 개선 후보 로그

주제 요청의 결과는 기본적으로 `/var/log/cineverse/topic-learning.jsonl`에
JSON Lines 형식으로 남긴다. 다음 정보만 기록한다.

- 주제 ID와 표시명
- 프로필/원문 중 어느 경로로 해석했는지
- 신뢰도와 사용한 검색·근거 단어
- 추천 성공 또는 확인 질문 여부
- 결과 영화의 TMDB ID와 제목

사용자 ID, 전체 질문, 대화 내용은 기록하지 않는다. 로그 저장 실패가 추천 API
장애로 이어지지 않도록 저장 오류는 비치명적으로 처리한다.

## 운영 개선 절차

로그가 쌓였다고 프로필이나 모델을 자동 변경하지 않는다. 자동 반영은 잘못된
표현과 공격성 입력이 검색 정책에 들어가는 데이터 오염 위험이 있다.

권장 절차는 다음과 같다.

1. 주 1회 `clarification_required`가 반복된 주제를 집계한다.
2. 운영자가 TMDB/DB 메타데이터와 실제 작품 내용을 확인한다.
3. 충분한 근거가 있는 별칭·검색어·근거어만 `topic_profiles.json`에 추가한다.
4. 오탐 영화와 정상 영화를 함께 회귀 테스트에 추가한다.
5. 전체 AI 테스트 통과 후 다음 정기 배포에 포함한다.

초기 프로필에는 실제 오류가 확인된 코딩·프로그래밍 소재만 포함한다. 새로운
주제는 로그 빈도만으로 추가하지 않고 반드시 사람의 검토를 거친다.

## 환경변수

```dotenv
TOPIC_PROFILE_PATH=/home/ubuntu/cineverse/data/topic_profiles.json
TOPIC_LEARNING_LOG_PATH=/var/log/cineverse/topic-learning.jsonl
```

운영 배포 시 프로필 파일을 위 경로에 두거나, 애플리케이션에 포함된 기본
`AI/data/topic_profiles.json`을 사용하도록 환경변수를 생략할 수 있다.
